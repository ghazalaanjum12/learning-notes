## 1. application.yml

### Properties to YAML conversion
Dotted keys in `application.properties` become nested YAML structure:

```properties
# application.properties
server.port=8080
spring.datasource.url=jdbc:mysql://localhost:3306/realworld_db
```

```yaml
# application.yml
server:
  port: 8080
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/realworld_db
```

### Key settings explained

| Setting | What it does |
|---|---|
| `show-sql: true` | Prints every SQL query Hibernate generates to the console. Useful for debugging, turn off in production |
| `open-in-view: false` | Closes DB session after business logic is done, not after response is rendered. Always set to `false` for REST APIs |
| `ddl-auto: update` | Hibernate automatically updates the DB schema based on your entities |

### Full application.yml
```yaml
spring:
  application:
    name: conduit

  jpa:
    hibernate:
      ddl-auto: update
    show-sql: true
    open-in-view: false

  datasource:
    url: jdbc:mysql://localhost:3306/realworld_db
    username: realworld_user
    password: realworld_pass
    driver-class-name: com.mysql.cj.jdbc.Driver
```

## 2. Docker & MySQL

### Useful Docker commands
```bash
# List running containers
docker ps

# Connect to MySQL inside container
docker exec -it mysql-container mysql -u realworld_user -p

# Get a full shell inside container
docker exec -it mysql-container bash
```

### `docker exec` vs `docker run`
| Command | What it does |
|---|---|
| `docker run` | Creates and starts a **new** container |
| `docker exec` | Runs a command in an **already running** container |

### MySQL commands
```sql
SHOW DATABASES;
USE realworld_db;
SHOW TABLES;
SELECT * FROM users;
DESCRIBE users;   -- shows table structure
DESC users;       -- shorthand
```

> **Note:** MySQL table names are case-sensitive on Linux. Use lowercase `users`, not `USERS`.
> Every MySQL command must end with a `;`

### Connecting via Docker Desktop
1. Open Docker Desktop → Containers tab
2. Click your MySQL container
3. Click the **Exec** tab
4. Type `mysql -u realworld_user -p`

## 3. OpenAPI Generator — Delegate Pattern

### Two patterns for using OpenAPI generator

**Pattern 1 — Without Delegate (implement UsersApi directly):**
```
Your Controller (implements UsersApi) → Your Service → Repository
```
```java
@RestController
public class UsersController implements UsersApi {
    @Override
    public ResponseEntity<UserResponse> createUser(CreateUserRequest body) {
        // your logic
    }
}
```

**Pattern 2 — With Delegate Pattern:**
```
Generated Controller → Your Delegate Impl → Your Service → Repository
```
```java
@Service
public class UsersApiDelegateImpl implements UsersApiDelegate {
    @Override
    public ResponseEntity<UserResponse> createUser(CreateUserRequest body) {
        // your logic
    }
}
```

### Key differences

| | Without Delegate | With Delegate |
|---|---|---|
| You override | `UsersApi` in a `@RestController` | `UsersApiDelegate` in a `@Service` |
| Generated controller | You write it | Already generated |
| Risk of regenerating | Method signatures may break | Safe, your code is separate |

### What's more common in industry?
- **Most teams skip the delegate pattern** — it's simpler and controllers feel natural
- Delegate pattern is more common in **large teams** where the spec changes frequently
- For smaller projects, implementing `UsersApi` directly is perfectly fine

### How routes work without delegate
The `@RequestMapping`/`@PostMapping` annotations live on the `UsersApi` interface, not your controller. When your controller `implements UsersApi`, it inherits those route mappings. Spring wires it automatically.

## 5. Entity — User.java

```java
@Entity
@Table(name = "users")
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.UUID)
    @Column(name = "id")
    private UUID id;

    @Column(name = "email", nullable = false, unique = true)
    private String email;

    @Column(name = "password", nullable = false)
    private String hashPassword;

    @Column(name = "username", nullable = false, unique = true)
    private String username;

    @Column(name = "bio")
    private String bio;

    @Column(name = "image_url")
    private String imageUrl;
}
```

## 6. Lombok Annotations

| Annotation | What it generates |
|---|---|
| `@Getter` | `getX()` for all fields |
| `@Setter` | `setX()` for all fields |
| `@NoArgsConstructor` | Constructor with no arguments |
| `@AllArgsConstructor` | Constructor with all fields |
| `@Builder` | Builder pattern — `User.builder().email("").build()` |
| `@Data` | `@Getter` + `@Setter` + `toString()` + `equals()` + `hashCode()` + `@RequiredArgsConstructor` |

### Why avoid `@Data` on JPA entities?
`@Data` generates `equals()` and `hashCode()` using all fields including `id`. Since `id` is `null` before saving and has a value after, the same object gets **different hashcodes** before and after saving — this breaks collections like `HashSet`.

Use `@Getter` + `@Setter` + `@NoArgsConstructor` + `@AllArgsConstructor` + `@Builder` instead.

## 7. Repository

```java
@Repository
public interface UserRepository extends JpaRepository<User, UUID> {
    Optional<User> findByEmail(String email);
    Optional<User> findByUsername(String username);
}
```

### Repository types explained

| Repository | Use case |
|---|---|
| `CrudRepository` | Basic CRUD — `save()`, `findById()`, `findAll()`, `delete()` |
| `JpaRepository` | CRUD + pagination + sorting + batch operations. **Use this for MySQL/PostgreSQL** |
| `MongoRepository` | Same as JpaRepository but for MongoDB |

Hierarchy: `CrudRepository` → `JpaRepository` → `MongoRepository`

Spring auto-generates queries from method names — `findByEmail()` works without writing any SQL.

## 8. Service Layer

### Do you need an interface?
**No** — for modern Spring Boot projects, just use a plain class:

```java
@Service
public class UserService {
    public UserResponse createUser(CreateUserRequest body) {
        // business logic
    }
}
```

The interface approach (`UserService` + `UserServiceImpl`) is an **old enterprise pattern** that adds boilerplate with no real benefit today since Mockito can mock concrete classes.

## 9. Spring Security

### Default behaviour
When `spring-boot-starter-security` is on the classpath with no config, Spring auto-creates:
- **Username:** `user`
- **Password:** randomly generated on every restart (shown in logs)

This causes **401 Unauthorized** on all requests until configured.

### SecurityConfiguration.java
```java
@Configuration
public class SecurityConfiguration {

    @Bean
    public PasswordEncoder encoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            .authorizeHttpRequests(auth -> auth
                .anyRequest().permitAll()
            );
        return http.build();
    }
}
```

This permits all requests for now. Later replace `anyRequest().permitAll()` with JWT authentication rules.

## 10. Enabling Debug Logs

```yaml
logging:
  level:
    org.springframework.security: DEBUG
    org.springframework.web: DEBUG
```

### Logging pattern
```yaml
logging:
  level:
    {package.name}: {LOG_LEVEL}
```

### Log levels (most → least verbose)
`TRACE` → `DEBUG` → `INFO` → `WARN` → `ERROR`

### Common packages to debug

| Problem | Package |
|---|---|
| Security / 401 / 403 | `org.springframework.security` |
| HTTP requests / routing | `org.springframework.web` |
| SQL queries | `org.hibernate.SQL` |
| DB parameters | `org.hibernate.orm.jdbc.bind` |
| Everything | `root` |

# Spring Security & JWT — Revision Notes

## 1. The `UserDetails` / `getUsername()` Conflict

When your `User` entity implements `UserDetails`, Spring Security requires `getUsername()` to return the **security principal** (used for JWT, session, etc.).

**Problem:** Lombok auto-generates `getUsername()` from a field named `username`, clashing with the `UserDetails` override that should return `email`.

**Solution — rename the field:**
```java
@Column(name = "username", nullable = false, unique = true)
private String handle; // renamed from username
```
- Lombok now generates `getHandle()` / `setHandle()`
- `getUsername()` override returns `email` unambiguously
- `@Column(name = "username")` stays the same — no DB migration needed

**Alternative — suppress Lombok's getter:**
```java
@Getter(AccessLevel.NONE)
@Column(name = "username", nullable = false, unique = true)
private String username;

public String getActualUsername() { return username; }

@Override
public String getUsername() { return email; } // for Spring Security
```

## 2. How "Get Current User" Works (Stateless HTTP)

HTTP is stateless, but the client stores the JWT received at login and sends it with every request:

```
Authorization: Token <jwt_token>
```

**Flow:**
1. User logs in → server returns JWT
2. Client stores JWT
3. Client calls `GET /api/user` with JWT in header
4. JWT filter validates token → sets authenticated user in `SecurityContext`
5. Controller retrieves the user from `SecurityContext`

## 3. `Token` vs `Bearer` Prefix

| Prefix | Used By |
|--------|---------|
| `Bearer` | Industry standard (RFC 6750), OAuth 2.0, most production APIs |
| `Token` | RealWorld spec, GitHub legacy PATs, some older APIs |

**Rule of thumb:** Always use `Bearer` in your own APIs. The RealWorld spec uses `Token` as a quirky custom choice — don't let it confuse your mental model.

The RealWorld spec defines it via OpenAPI:
```yaml
securitySchemes:
  Token:
    type: http
    scheme: bearer
```
The scheme name `Token` drives the header prefix by convention.

## 4. Substring Gotcha — `Token` vs `Bearer`

| Prefix | Length | Correct substring |
|--------|--------|-------------------|
| `Bearer ` | 7 chars | `substring(7)` |
| `Token ` | 6 chars | `substring(6)` |

```java
// ❌ Wrong for RealWorld spec
final String jwt = authHeader.substring(7); // chops first char of JWT

// ✅ Correct
final String jwt = authHeader.substring(6);
```

Stripping the wrong number of characters corrupts the JWT and causes `MalformedJwtException`.

## 5. JWT Authentication Filter

```java
@Override
protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain)
        throws ServletException, IOException {

    final String authHeader = request.getHeader("Authorization");

    if (authHeader == null || !authHeader.startsWith("Token ")) {
        filterChain.doFilter(request, response);
        return;
    }

    try {
        final String jwt = authHeader.substring(6); // "Token " = 6 chars
        final String userEmail = jwtService.extractUsername(jwt);
        Authentication authentication = SecurityContextHolder.getContext().getAuthentication();

        if (userEmail != null && authentication == null) {
            UserDetails userDetails = userDetailsService.loadUserByUsername(userEmail);
            if (jwtService.isTokenValid(jwt, userDetails)) {
                UsernamePasswordAuthenticationToken authToken =
                    new UsernamePasswordAuthenticationToken(userDetails, null, userDetails.getAuthorities());
                authToken.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
                SecurityContextHolder.getContext().setAuthentication(authToken);
            }
        }
    } catch (Exception exception) {
        handlerExceptionResolver.resolveException(request, response, null, exception);
    }
}
```

## 6. Getting the Current User

### Option A — `@AuthenticationPrincipal` (clean, but modifies controller)
```java
@GetMapping("/api/user")
public ResponseEntity<?> getCurrentUser(@AuthenticationPrincipal User user) {
    return ResponseEntity.ok(userService.getCurrentUser(user));
}
```

### Option B — From `SecurityContext` in Service (safe with generated controllers)
```java
// Controller — untouched as generated
public ResponseEntity<?> getCurrentUser() {
    return ResponseEntity.ok(userService.getCurrentUser());
}

// Service
public UserDTO getCurrentUser() {
    User user = (User) SecurityContextHolder.getContext().getAuthentication().getPrincipal();
    return userMapper.toUserDTO(user);
}
```

**Why Option B?** If your controller is OpenAPI-generated, it may be regenerated and overwrite any changes. Fetching the principal in the service keeps the controller untouched.

## 7. Layer Responsibilities

| Layer | Responsibility |
|-------|---------------|
| Controller | Receive request, call service, return response |
| Service | Business logic, fetch principal, map entity → DTO |
| Repository | Database access |

**Never return entities directly from controllers** — they can expose sensitive fields like `hashPassword`. Always map to a DTO in the service layer.

## 8. Debugging Lombok-generated Code

- Always set breakpoints in the **`.java` source file**, not the `.class` file
- The `.class` file is compiled bytecode — your IDE decompiles it for readability but you can't debug there
- To verify constructor injection, inspect `this` in the variables panel when paused at the first line of any method
- To check at construction time, temporarily add a manual constructor, set a breakpoint, then remove it after verifying

---

## 9. `@AuthenticationPrincipal` — Entity or DTO?

It returns the **entity** — whatever `loadUserByUsername()` returns in your `UserDetailsService`. The filter stores the full entity as the principal:

```java
new UsernamePasswordAuthenticationToken(userDetails, null, userDetails.getAuthorities());
//                                       ^^^^^^^^^^^ this is your User entity
```

`@AuthenticationPrincipal` just pulls that same object back out. Always map it to a DTO before returning from the service.

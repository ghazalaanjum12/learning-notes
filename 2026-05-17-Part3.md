## 1. Spring Security — Debugging 401 Errors

When a request returns 401, Spring Security is blocking it. Common signs in logs:

- `AnonymousAuthenticationFilter` — no real auth found
- `HttpSessionRequestCache` — request is being saved for redirect
- `DelegatingAuthenticationEntryPoint` — falling back to Basic Auth

### Fix Options

**Permit specific endpoint:**
```java
http.authorizeHttpRequests(auth -> auth
    .requestMatchers("/test").permitAll()
    .anyRequest().authenticated()
);
```

**Permit everything (dev only):**
```java
http.authorizeHttpRequests(auth -> auth
    .anyRequest().permitAll()
);
```

**Pass credentials manually:**
```bash
curl -u username:password http://localhost:8080/test
```

## 2. SecurityConfiguration — What It Does

```java
@Configuration
public class SecurityConfiguration {

    @Bean
    public PasswordEncoder encoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            .authorizeHttpRequests(auth -> auth
                .anyRequest().permitAll()
            );
        return http.build();
    }
}
```

### PasswordEncoder Bean
- Registers BCrypt as the hashing algorithm
- Spring uses this automatically when hashing or verifying passwords

### SecurityFilterChain Bean
- `.csrf().disable()` — turns off CSRF protection (correct for JWT-based REST APIs)
- `.anyRequest().permitAll()` — allows all requests through with no authentication

## 3. CSRF — Cross-Site Request Forgery

### What the Attack Looks Like
- You're logged into `bank.com`, browser holds a session cookie
- You visit `evil.com` which has a hidden form that submits to `bank.com`
- Browser auto-sends the cookie, bank processes the forged request

### The Fix (CSRF Token)
- Server embeds a secret token in every HTML form
- On POST, server checks the token matches
- `evil.com` can't know the token → forged request rejected

### Why We Disable It in REST APIs
- REST APIs use **JWT tokens in Authorization headers**, not cookies
- `evil.com` can't read your JWT (stored in memory/localStorage, not auto-sent)
- No cookies = no CSRF risk

### Origin
- Major concern in the **server-rendered HTML era** (early 2000s Java/PHP/Rails apps)
- CSRF tokens were the standard defense for session-cookie-based apps

## 4. HttpSecurity

A **builder object** for configuring HTTP-layer security behaviour. Think of it as a fluent configuration DSL:

```java
http
    .csrf(...)                   // configure CSRF
    .sessionManagement()         // stateless vs stateful
    .authorizeHttpRequests()     // who can access what
    .addFilterBefore()           // inject custom filters (e.g. JWT)
```

Spring passes it into your method, you configure it, `.build()` produces the filter chain.

---

## 5. SecurityFilterChain

Every HTTP request passes through a **chain of filters** before hitting your controller:

```
Request → [Filter1] → [Filter2] → [JWTFilter] → [AuthFilter] → Controller
```

`SecurityFilterChain` is that chain. Returning it as a `@Bean` tells Spring which security filters every request must pass through.

## 6. Old vs New Security Configuration

### Old Way (`WebSecurityConfigurerAdapter`)
```java
@Configuration
@EnableWebSecurity
public class SecurityConfig extends WebSecurityConfigurerAdapter {

    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http
            .csrf().disable()
            .authorizeRequests()
            .anyRequest().permitAll();
    }
}
```
- Extend a base class and override methods
- Spring calls your overridden `configure()` internally
- `@EnableWebSecurity` required to signal "I'm taking over security config"

### New Way (Spring Security 5.7+)
```java
@Configuration
public class SecurityConfiguration {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            .authorizeHttpRequests(auth -> auth
                .anyRequest().permitAll()
            );
        return http.build();
    }
}
```
- Plain `@Configuration` class, no inheritance
- Return the filter chain as a `@Bean` directly
- `@EnableWebSecurity` is now optional (auto-applied by Spring Boot)

### Comparison

| | Old | New |
|---|---|---|
| Style | Extend class, override method | Return `@Bean` |
| `@EnableWebSecurity` | Required | Optional in Boot |
| `WebSecurityConfigurerAdapter` | Required | Deprecated & removed in Spring Security 6 |
| Flexibility | Harder to compose | Easier — multiple filter chains possible |

## 7. `@EnableWebSecurity`

### What It Imports
```java
@Import({ WebSecurityConfiguration.class,
          SpringWebMvcImportSelector.class,
          OAuth2ImportSelector.class,
          HttpSecurityConfiguration.class })
@EnableGlobalAuthentication
public @interface EnableWebSecurity {}
```

- **`WebSecurityConfiguration`** — creates `FilterChainProxy`, the master filter
- **`HttpSecurityConfiguration`** — makes `HttpSecurity` available for injection
- **`EnableGlobalAuthentication`** — sets up the `AuthenticationManager`

### Is It Auto-Applied with Spring Boot?

Yes. When you add `spring-boot-starter-security`, Boot's auto-configuration applies it:

```
SecurityAutoConfiguration
  └── SpringBootWebSecurityConfiguration
        └── @EnableWebSecurity  ← applied automatically
```

### When to Add It Explicitly

| Situation | Need it? |
|---|---|
| Spring Boot + starter-security | No, auto-applied |
| Plain Spring (no Boot) | Yes, required |
| Want debug mode | Yes — `@EnableWebSecurity(debug = true)` |

`debug = true` logs every filter decision — useful for diagnosing 401 errors.


```sql

```

### Comparison

| | `DELETE FROM users` | `TRUNCATE TABLE users` |
|---|---|---|
| Removes all rows | ✅ | ✅ |
| Resets auto-increment | ❌ | ✅ |
| Supports `WHERE` clause | ✅ | ❌ |
| Speed on large tables | Slower | Faster |

## 9. MapStruct

### What It Solves

Instead of manually mapping fields:
```java
User user = new User();
user.setUsername(newUser.getUsername());
user.setEmail(newUser.getEmail());
user.setHashPassword(passwordEncoder.encode(newUser.getPassword()));
```

You define an interface and MapStruct generates the implementation at **compile time**.

### Version to Use

| Spring Boot | Java minimum | MapStruct |
|---|---|---|
| 2.x | 8 | 1.5.x |
| 3.x | 17 | 1.6.x |
| 4.x | 17 | 1.6.3 (stable) |

Spring Boot 4 requires Java 17+. MapStruct 1.7 is still in Beta — avoid in production.

### pom.xml Setup

```xml
<!-- Under <dependencies> -->
<dependency>
    <groupId>org.mapstruct</groupId>
    <artifactId>mapstruct</artifactId>
    <version>1.6.3</version>
</dependency>

<!-- Under <build><plugins> -->
<build>
    <plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <configuration>
                <annotationProcessorPaths>
                    <path>
                        <groupId>org.mapstruct</groupId>
                        <artifactId>mapstruct-processor</artifactId>
                        <version>1.6.3</version>
                    </path>
                </annotationProcessorPaths>
            </configuration>
        </plugin>
    </plugins>
</build>
```

### Two Separate Pieces

| Piece | Where | Purpose |
|---|---|---|
| `mapstruct` | `<dependencies>` | Annotations your code uses (`@Mapper`, `@Mapping`) |
| `mapstruct-processor` | `<build><plugins>` | Code generator that runs at compile time |

### Basic Mapper

```java
@Mapper(componentModel = "spring")
public interface UserMapper {

    @Mapping(target = "id", ignore = true)
    @Mapping(target = "hashPassword", ignore = true)
    @Mapping(target = "bio", ignore = true)
    @Mapping(target = "image", ignore = true)
    User newUserToUser(NewUser newUser);
}
```

- `componentModel = "spring"` — generates a Spring bean, so you can `@Autowired` it
- Fields with matching names map automatically
- Use `@Mapping(target = "field", ignore = true)` for fields that don't exist in the source

### Service Using Mapper

```java
@Service
public class RegistrationService {

    @Autowired private PasswordEncoder passwordEncoder;
    @Autowired private UserRepository userRepository;
    @Autowired private UserMapper userMapper;

    public User registerUser(NewUser newUser) {
        User user = userMapper.newUserToUser(newUser);
        user.setHashPassword(passwordEncoder.encode(newUser.getPassword()));
        return userRepository.save(user);
    }
}
```

### Why hashPassword Is Still Manual
MapStruct maps by **name matching** — `NewUser` has `password`, `User` has `hashPassword`, and the value needs to be encoded, not just copied. MapStruct can't know that logic, so you ignore it in the mapper and handle it yourself.

### Ignoring Unmapped Fields

**Per field (recommended — keeps compile-time safety):**
```java
@Mapping(target = "id", ignore = true)
@Mapping(target = "hashPassword", ignore = true)
```

**Globally for the mapper (loses safety net — use carefully):**
```java
@Mapper(componentModel = "spring",
        unmappedTargetPolicy = ReportingPolicy.IGNORE)
public interface UserMapper { ... }
```

## 10. Package Structure Convention

```
com.conduit
├── controller
├── service
├── repository
├── entity
├── dto          ← POJOs / request / response objects
└── mapper       ← MapStruct interfaces
```

### Mapper Naming
Name mappers after the entity, not the use case:

```
mapper/
├── UserMapper.java       ✅
├── ArticleMapper.java    ✅
└── NewUserToUserMapper   ❌ (too specific)
```

One mapper handles all mappings for that entity in both directions:

```java
@Mapper(componentModel = "spring")
public interface UserMapper {
    User newUserToUser(NewUser newUser);           // registration
    UserResponse userToUserResponse(User user);    // returning user data
}
```

## Key Takeaways

- Spring Security blocks all requests by default — configure explicitly what's permitted
- CSRF protection is for cookie/session apps — disable it for JWT REST APIs
- The new `SecurityFilterChain` bean approach replaced `WebSecurityConfigurerAdapter` in Spring Security 6
- `@EnableWebSecurity` is auto-applied by Spring Boot — only add it manually for plain Spring or debug mode
- MapStruct generates mapping code at compile time — mismatches are caught before runtime
- Match your MapStruct version to your Spring Boot/Java version — use `1.6.3` for Boot 4.x
- The `mapstruct` dependency and `mapstruct-processor` plugin are two separate things serving different purposes

## 1. JsonNullable

`JsonNullable` is not a standard Java collection. It comes from the **Jackson Databind Nullable** library, used mainly with OpenAPI-generated code.

### The Three States
```java
JsonNullable.undefined()    // field was absent from JSON — don't touch it
JsonNullable.of(null)       // field was explicitly set to null
JsonNullable.of("Hello!")   // field has a real value
```

### Why It Matters
Useful for **PATCH requests** — lets you distinguish between "client didn't send this field" vs "client explicitly set it to null":
```java
if (bio.isPresent()) {
    user.setBio(bio.get());   // only update if client sent the field
}
```

## 2. Password Security — BCrypt

### The Golden Rule
**Never store plaintext passwords.** Store a one-way hash instead.

### Why BCrypt
| Property | What it means |
|---|---|
| Salted | Random salt per password — same password = different hashes |
| Slow by design | Expensive to compute, brute-force attacks are impractical |
| Work factor | Cost can be increased over time as hardware improves |

### Setup
```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>
```

```java
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder(12); // cost factor 12
}
```

### Usage
```java
// Registration — encode once, store the result
user.setHashedPassword(passwordEncoder.encode(rawPassword));

// Login — re-hash with same salt and compare
passwordEncoder.matches(rawPassword, storedHash); // returns true/false
```

### BCrypt stored in DB
```
$2a$12$eImiTXuWVxfM37uY4JANjQ==.WaD6R2oHDyJVN0bPpT/kxMD1mF0W
          └──── salt ─────┘    └───────── hash ───────────────┘
```

### Industry Usage
| Algorithm | Status |
|---|---|
| BCrypt | ✅ Industry standard, battle-tested |
| Argon2 | ✅ Modern best practice |
| SCrypt | ✅ Good, memory-hard |
| MD5 / SHA-1 | ❌ Never use — outdated and cracked |

## 3. What is a Salt?

A **salt** is a random string added to a password before hashing it.

### Without Salt — Vulnerable
```
"password123" → hash → 482c811da5d5b4bc6d497ffa98491e38  (same every time)
```
Attackers use **Rainbow Tables** — precomputed hash lookups — to instantly reverse hashes.

### With Salt — Safe
```
"password123" + "xK9#mQ2p" (salt) → hash → 9f4a2b...  (unique!)
"password123" + "zR7!nL5w" (salt) → hash → 3c8e1f...  (unique!)
```

The salt is stored inside the BCrypt hash string and extracted automatically at login — you never handle it manually.

---

## 4. How BCrypt `matches()` Works

```
REGISTRATION
────────────────────────────────────────────
1. BCrypt generates random salt → "xK9#mQ2p"
2. Hashes ("password123" + "xK9#mQ2p")
3. Stores: $2a$12$...(salt)...(hash)...

LOGIN
────────────────────────────────────────────
1. BCrypt EXTRACTS salt from stored hash
2. Hashes (inputPassword + extracted salt)
3. Compares result with stored hash
4. Match? ✅ → true. No match? ❌ → false
```

## 6. Entity Annotations

### `@Entity`
Marks a class as a JPA entity — maps it to a database table.

### `@Table`
Controls the table name and table-level constraints:
```java
@Entity
@Table(
    name = "users",
    uniqueConstraints = {
        @UniqueConstraint(columnNames = {"email"}),
        @UniqueConstraint(columnNames = {"username"})
    }
)
public class User { }
```

### `@Column`
Controls individual column properties:
```java
@Column(nullable = false, unique = true, length = 100)
private String email;
```

| Option | What it does | Default |
|---|---|---|
| `name` | Column name in DB | field name |
| `nullable` | NOT NULL constraint | `true` |
| `unique` | UNIQUE constraint | `false` |
| `length` | VARCHAR length | `255` |

### Multi-column constraint with `@Table`
```java
@Table(
    name = "follows",
    uniqueConstraints = {
        @UniqueConstraint(columnNames = {"follower_id", "following_id"})
    }
)
```
Ensures the **combination** is unique — useful for follow/unfollow relationships.

## 7. Primary Keys — `@Id`

`@Id` marks a field as the primary key. Every JPA entity must have one.

```java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

A primary key is automatically: **Unique + Not Null + Indexed**

---

## 8. Generation Types

| Strategy | Generates | Notes |
|---|---|---|
| `IDENTITY` | 1, 2, 3... | DB auto-increment, most common |
| `SEQUENCE` | 1, 2, 3... | Faster than IDENTITY, preferred by Hibernate |
| `UUID` | 550e8400-... | Non-guessable, safe for public APIs |
| `AUTO` | Hibernate decides | Avoid in production — unpredictable |

---

## 9. UUID vs Incremental ID

| | Incremental (Long) | UUID |
|---|---|---|
| Guessable | ✅ Yes — security risk | ❌ No |
| Reveals user count | ✅ Yes | ❌ No |
| Performance | Slightly faster | Slightly slower |
| Use when | ID is internal only | ID exposed in URLs/API |

### `java.util.UUID` vs `GenerationType.UUID`
| | Role |
|---|---|
| `java.util.UUID` | The Java **type** — like a box that holds the value |
| `GenerationType.UUID` | Hibernate's **generator** — fills the box automatically |

## 10. Validation — Two Layers

### Layer 1 — DTO (Request) Level
Catches bad input before any logic runs:
```java
public class RegisterUserRequest {
    @NotBlank
    @Email
    private String email;

    @NotBlank
    @Size(min = 3, max = 50)
    private String username;

    @NotBlank
    @Size(min = 8)
    private String password;
}
```

Dependency needed:
```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

### Layer 2 — Entity Level
Defines the DB schema constraints:
```java
@Column(nullable = false, unique = true)
private String email;
```

### The Flow
```
Request → @NotBlank/@Email (caught early, clean 400 error)
        → Service logic
        → @Column(nullable=false) (last line of defence)
        → Database
```

### Common Validation Annotations
| Annotation | Checks |
|---|---|
| `@NotBlank` | Not null AND not empty string |
| `@NotNull` | Not null (empty string is ok) |
| `@Email` | Valid email format |
| `@Size(min, max)` | String length |
| `@Min` / `@Max` | Number range |

```
HTTP Request JSON
      │
      ▼
┌─────────────────┐
│   Request DTO   │  ← @NotBlank, @Email validations here

│   Request       │
└─────────────────┘
      │  Service maps DTO → Entity
      ▼
┌─────────────────┐
│     Entity      │  ← @Column constraints here
│    (User)       │  ← has hashed password
└─────────────────┘
      │
      ▼
   Database
```

## 12. Full User Entity Example

```java
@Entity
@Table(name = "users")
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true, length = 100)
    private String email;

    @Column(nullable = false, unique = true, length = 50)
    private String username;

    @Column(name = "hashed_password", nullable = false)
    private String hashedPassword;

    @Column(length = 500)
    private String bio;

    @Column(name = "image_url")
    private String image;
}
```

## 13. Hibernate DDL Auto

Controls whether Hibernate creates/alters your DB tables automatically:

```properties
spring.jpa.hibernate.ddl-auto=update
```

| Value | What it does |
|---|---|
| `create` | Drops and recreates tables every startup |
| `create-drop` | Creates on startup, drops on shutdown |
| `update` | Creates/alters tables to match entities |
| `validate` | Checks entities match DB, touches nothing |
| `none` | Does nothing — you manage schema yourself |

### Environment Strategy
```
Development  →  ddl-auto=update    (fast iteration)
Production   →  ddl-auto=validate  (use Flyway/Liquibase)
```

## 14. Flyway — Database Migration Tool

Manages schema changes over time in a controlled, trackable way.

### Migration Files
```
src/main/resources/db/migration/
    V1__create_users_table.sql
    V2__add_bio_to_users.sql
    V3__create_follows_table.sql
```

Each file runs **exactly once**, tracked in `flyway_schema_history` table.

### With Spring Boot
```properties
spring.jpa.hibernate.ddl-auto=validate
spring.flyway.enabled=true
```

### Flyway vs Liquibase
| | Flyway | Liquibase |
|---|---|---|
| Write in | Plain SQL | SQL, XML, YAML, JSON |
| Learning curve | Simpler | More complex |
| Rollback | Limited | Better support |

> 💡 Similar concept to ImpEx/InitialData in SAP Commerce Cloud.

## 15. Docker

### Image vs Container vs Volume

| Docker | Java analogy | Description |
|---|---|---|
| Image | Class | Blueprint — static, never changes |
| Container | Object | Running instance — disposable |
| Volume | External DB | Persistent storage — survives container deletion |

### `docker-compose.yml`
```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: realworld_mysql
    environment:
      MYSQL_ROOT_PASSWORD: rootpassword
      MYSQL_DATABASE: realworld_db
      MYSQL_USER: realworld_user
      MYSQL_PASSWORD: realworld_pass
    ports:
      - "3307:3306"      # hostPort:containerPort
    volumes:
      - mysql_data:/var/lib/mysql

volumes:
  mysql_data:
```

### Port Mapping
```
"3307:3306"
  │      │
  │      └── MySQL port INSIDE the container (always 3306)
  └── port on YOUR machine to reach it
```

### Useful Commands
```bash
docker compose up -d        # start containers in background
docker compose down         # stop containers (data preserved)
docker compose down -v      # stop AND delete volumes (fresh start)
docker ps                   # list running containers
docker logs realworld_mysql # view container logs
```

### `application.properties` for Docker MySQL
```properties
spring.datasource.url=jdbc:mysql://localhost:3307/realworld_db
spring.datasource.username=realworld_user
spring.datasource.password=realworld_pass
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
```

> ⚠️ Hibernate creates tables but NOT the database itself. Create the database manually first:
> ```sql
> CREATE DATABASE realworld_db;
> ```

### Port Conflict Error Fix
If you get `ports are not available: 3306`, your local MySQL is already using that port:
- **Option 1**: Stop local MySQL service (`net stop mysql80` on Windows)
- **Option 2**: Change Docker port to `"3307:3306"` and update `application.properties`

## 16. Maven Dependency Scopes

| Scope | Compile | Runtime | Test | Bundled in jar | Use for |
|---|---|---|---|---|---|
| `compile` (default) | ✅ | ✅ | ✅ | ✅ | Most dependencies |
| `runtime` | ❌ | ✅ | ✅ | ✅ | DB drivers, logging |
| `test` | ✅ | ✅ | ✅ | ❌ | JUnit, Mockito |
| `provided` | ✅ | ❌ | ✅ | ❌ | Servlet API |
| `system` | ✅ | ❌ | ✅ | ❌ | Local jars (avoid) |
| `import` | — | — | — | — | POM imports only |

### In practice you'll mostly use 3:
```xml
<!-- compile (default) — most dependencies -->
<dependency>...</dependency>

<!-- runtime — DB drivers -->
<dependency>
    <scope>runtime</scope>
</dependency>

<!-- test — JUnit, Mockito, H2 -->
<dependency>
    <scope>test</scope>
</dependency>
```

## 17. pom.xml — groupId, artifactId, version

Think of it like finding a book in a library:

| Field | Analogy | Example |
|---|---|---|
| `groupId` | Organisation/Author | `org.springframework.boot` |
| `artifactId` | Book title | `spring-boot-starter-data-jpa` |
| `version` | Edition | `3.2.0` |

With Spring Boot's parent pom, version is managed automatically — no need to specify it manually for Spring dependencies:
```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.2.0</version>
</parent>
```
